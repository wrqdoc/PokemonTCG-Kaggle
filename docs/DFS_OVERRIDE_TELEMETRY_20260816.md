# DFS 到底改变多少决策：当前包的直接实测（2026-08-16）

> 被测包：`bc_prize_search_dfs_grimmsnarl_deckv3_xopt810_v1`（DX）
> 对手：`pure_bc_grimmsnarl_deckv3top_xopt810_v1`（冠军 X）
> **200 局、19,424 个决策、0 engine error。**
> 工具：`scratchpad/instrument_dfs_telemetry.py` → `closed_loop/common_ref_dfs_override_telemetry_20260816/`

---

## 0. 为什么必须重测

**当前的 DFS 包没有定义 `SEARCH_STATS`。** 评测框架的 diagnostics 钩子只读
`SEARCH_STATS` / `RUNTIME_STATS` 两个模块级全局量，所以**搜索层此前是完全的黑盒**。

⚠️ 一个已经造成误读的坑：D 的 1200 局遥测里有 21,851 条"没走 BC"的决策
（`runtime_decisions − runtime_route_bc_used`）。**那不是搜索覆盖**——它恰好等于
`runtime_fallback_total` 与 `runtime_route_empty_action`，是空动作 fallback，
纯 BC 包里同样存在。**拿它当搜索活动量会高估约 2 个数量级。**

台账与主计划里那些数字（"仅改变 1.8% MAIN 决策"、"v4 的 7 次 override / 48 局"）
都来自更老的构建，**不描述当前这个包**。

被至少一次覆盖触及的对局      57/200 = 28.5%   95% CI [22.7, 35.1]

## 2. 三条读法

**① 两个分母差两个数量级，必须报对局那个。**
0.329% 的决策占比看着可以忽略，但它触及 **28.5% 的对局**——约每 3.5 局就有一局
被改动过。这正是台账 2026-08-05 那条更正：*"正确的分母是被触及的对局比例，不是决策比例"*
（当时 v4 是 0.162% 决策 / 10.4% 对局）。**当前包两个口径都比 v4 高约 2–3 倍。**

**② 覆盖门没有空转：64 次证明，64 次都改变了动作，0 次与 BC 重合。**
源码的覆盖条件是"两次确定化取 min，且必须严格优于 BC 首选"
（`DETERMINIZATIONS = 2`，模块注释：*"nothing overrides it without proof"*）。
实测说明这道门**极保守但不冗余**——它一旦开口，就一定在改事情。
（对照 §3.3：v5 配对布局是"37 次尝试、35 次完成、**0 次 override**"，那才是空转。）

**③ 每局最多 2 次。** median 0、p90 1、max 2。搜索不是持续接管，是偶发点状干预。

## 3. 对提交决策的含义

**DX 与冠军 X 的行为差异 = 0.329% 的决策、28.5% 的对局。**
这解释了为什么两者在 1200/500 局的镜像 H2H 里分辨不出（DX 52.60%，CI [48.22,56.94]）：
改动量本来就小。

⚠️ **由此推翻本人 8-15 的一个论证**：当时反对"同时交两个 DFS 包"，理由是
"共用搜索层 → 相关失败"。**该论证方向错误**：搜索层只造成 0.329% 的决策差异，
而**换 checkpoint 会改变整个策略网络**。故：

| 组合 | 两包的真实差异 |
|---|---|
| X + DX | 仅差搜索层 → **0.329% 决策不同**，近似同一策略交两遍 |
| **D + DX** | **不同 checkpoint** → 整个网络不同 |

→ 在"名次取两个提交的较高者"规则下，**D + DX 是分散度更高的一对**；
把其中一个换成纯 X 是用对冲换冗余。
